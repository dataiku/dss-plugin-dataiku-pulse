# Dataiku Pulse 3.1.1 Release Notes

**Release status:** Release candidate  
**Release period:** September 2026

## What this release delivers

Version 3.1.1 adds license-utilization reporting and Project Standards workflows, improves GOLD build reliability and dashboard loading, strengthens large SILVER maintenance, and corrects direct DuckDB access for S3 connections that require path-style requests. No manual schema migration is required.

## Release highlights

### License utilization reporting

Pulse now includes license utilization reporting backed by new dashboard APIs and a dedicated dashboard experience. It brings current license capacity and utilization information together with related user context so operators can review adoption and available capacity more directly.

### Project Standards workflows

Project Standards can now be launched from Pulse project detail views. Runs execute in the background and their cached reports can be opened from the dashboard when available. The experience surfaces scheduling failures, supports a local cache recheck, and uses clearer result labels: a zero-severity result is shown as Success, while execution outcome remains distinct.

### More resilient and efficient GOLD processing

GOLD creation now aligns user-activity source construction with the existing incremental correction window, reducing routine reads of historical SILVER data while retaining full-build behavior when an incremental watermark is unavailable. The release also improves incremental unload correctness, adds phase timing, validates required dashboard GOLD tables, and improves dashboard reload diagnostics and partial-failure reporting.

### Amazon S3 path-style support for DuckDB

Pulse now carries the Dataiku S3 connection setting `usePathMode` into DuckDB secret configuration. For connections that require path-style addressing, DuckDB reads the same logical `s3://` URI through the required path-style HTTPS request. This corrects GOLD build failures where DuckDB’s virtual-host default could not list SILVER data even though Dataiku managed-folder access was working.

### Maintenance and platform hardening

Compact SILVER maintenance now batches eligible S3 partition reads and applies a stage-level DuckDB memory cap. Dashboard startup and reload behavior has been hardened with safer local configuration fallbacks, more reliable DuckDB-path freshness handling, and improved bulk loading. The release also includes a WeasyPrint dependency update from the security audit.

## Bug fixes and patches

- Corrected incremental GOLD unload behavior and aligned user-activity GOLD construction with the existing incremental lookback window.
- Improved dashboard startup freshness detection, daily fact bulk loading, reload diagnostics, and partial-reload failure visibility.
- Added explicit validation for required dashboard GOLD tables before dashboard data is used.
- Corrected Project Standards result wording so severity zero is presented as Success, distinct from a completed execution outcome.
- Added S3 path-style support to prevent DuckDB GOLD reads from failing on Dataiku connections configured with `usePathMode` enabled.
- Updated WeasyPrint as part of security-audit maintenance.

## Upgrade and operator notes

- No manual database or schema migration is required for this release.
- After deployment, run the normal data-gather workflows and Create GOLD Tables recipe to populate the new and updated dashboard reporting outputs.
- For Dataiku S3 connections configured with `usePathMode` enabled, deploy the complete 3.1.1 plugin before rerunning Create GOLD Tables. The fix applies during DuckDB secret creation and subsequent STS credential refresh.
- Compact SILVER Layer remains an administrator-operated maintenance capability. Start with a restricted module scope and review its audit output before a broader historical repair.
- Project Standards reports are cached. A completed background run may require a short availability refresh before its report can be opened in Pulse.

## Validation and release readiness

The 3.1.1 changes include focused automated coverage for the new license, Project Standards, GOLD, dashboard, Compact SILVER, and DuckDB storage behavior. The S3 path-style correction has also been reproduced independently with the affected connection: virtual-host addressing failed, while path-style addressing read the expected SILVER parquet object.

Before broad release, deploy the packaged plugin to the affected DSS environment and rerun Create GOLD Tables against the path-style S3 connection. Confirm that the GOLD recipe reads SILVER successfully in the deployed runtime.

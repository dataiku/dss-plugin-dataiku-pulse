# Dataiku Pulse 3.1.1

## What This Release Delivers

Dataiku Pulse 3.1.1 introduces **license-utilization reporting** and **Project Standards workflows**, while improving **GOLD build reliability**, **dashboard loading**, and **large-scale SILVER maintenance**.

The release also corrects direct DuckDB access for Amazon S3 connections that require **path-style requests**.

**No manual database or schema migration is required.**

---

## Release Highlights

### License Utilization Reporting

Pulse now includes license-utilization reporting backed by new dashboard APIs and a dedicated dashboard experience.

The new reporting brings current license capacity and utilization information together with related user context, allowing operators to review adoption and available capacity more directly.

### Project Standards Workflows

Project Standards can now be launched directly from Pulse project-detail views.

Runs execute in the background, and cached reports can be opened from the dashboard when available. The experience also:

* Surfaces scheduling failures.
* Supports a local cache recheck.
* Provides clearer result labels.
* Displays a zero-severity result as **Success**.
* Keeps execution outcome distinct from the severity of the resulting report.

### More Resilient and Efficient GOLD Processing

GOLD creation now aligns user-activity source construction with the existing incremental correction window. This reduces routine reads of historical SILVER data while retaining full-build behavior when an incremental watermark is unavailable.

The release also improves:

* Incremental unload correctness.
* GOLD processing phase timing.
* Required dashboard GOLD-table validation.
* Dashboard reload diagnostics.
* Partial-failure reporting.

### Amazon S3 Path-Style Support for DuckDB

Pulse now carries the Dataiku S3 connection setting `usePathMode` into DuckDB secret configuration.

For connections that require path-style addressing, DuckDB reads the same logical `s3://` URI using the required path-style HTTPS request.

This corrects GOLD-build failures where DuckDB's default virtual-host addressing could not list SILVER data even though Dataiku-managed-folder access was working correctly.

### Maintenance and Platform Hardening

Compact SILVER maintenance now:

* Batches eligible S3 partition reads.
* Applies a stage-level DuckDB memory cap.

Dashboard startup and reload behavior has also been hardened with:

* Safer local-configuration fallbacks.
* More reliable DuckDB-path freshness handling.
* Improved bulk loading.
* Enhanced reload diagnostics.

The release additionally includes a **WeasyPrint dependency update** as part of security-audit maintenance.

## Bug Fixes and Patches

* Corrected incremental GOLD unload behavior and aligned user-activity GOLD construction with the existing incremental lookback window.
* Improved dashboard startup freshness detection, daily fact bulk loading, reload diagnostics, and partial-reload failure visibility.
* Added explicit validation for required dashboard GOLD tables before dashboard data is used.
* Corrected Project Standards result wording so severity zero is presented as **Success**, distinct from a completed execution outcome.
* Added S3 path-style support to prevent DuckDB GOLD reads from failing on Dataiku connections configured with `usePathMode` enabled.
* Updated WeasyPrint as part of security-audit maintenance.

---

## Upgrade and Operator Notes

* **No manual database or schema migration is required** for this release.
* After deployment, run the normal data-gather workflows and **Create GOLD Tables** recipe to populate the new and updated dashboard reporting outputs.
* For Dataiku S3 connections configured with `usePathMode` enabled, deploy the complete **3.1.1 plugin** before rerunning **Create GOLD Tables**. The fix applies during DuckDB secret creation and subsequent STS credential refresh.
* **Compact SILVER Layer** remains an administrator-operated maintenance capability. Start with a restricted module scope and review its audit output before performing a broader historical repair.
* **Project Standards reports are cached.** A completed background run may require a short availability refresh before its report can be opened in Pulse.

# Dataiku Pulse 3.2.1

## User Activity History-Aware Reporting

User Activity reporting now accounts for the amount of historical data actually available.

### 30-Day Metrics

* 30-day User Activity metrics now display available values even when less than 30 days of history have been collected.
* These early values are clearly marked as **Partial history**.

### Longer Reporting Windows

Longer reporting windows remain protected from incomplete comparisons:

| Reporting Window |                   Required History |
| ---------------- | ---------------------------------: |
| **30 days**      | Available history may be displayed |
| **90 days**      |                            90 days |
| **6 months**     |                           183 days |
| **12 months**    |                           365 days |

The following six-month tiles now follow the same coverage requirement:

* **Inactive users (6 months)**
* **View-only users (6 months)**

These tiles display `-` until sufficient history is available.

---

## User Analytics Filter Reliability

Filtering behavior has been corrected for consumer license profiles.

The following areas are specifically addressed:

* **User Segments** when filtering by consumer license profiles.
* **User Leaderboards** when filtering by consumer license profiles.
* Consumer, creator, and default activity views when applying configured profile exclusions.

These views now correctly apply their configured profile exclusions without query-binding or field-reference failures.

---

## Dashboard Startup Reliability

DuckDB initialization has been strengthened to prevent concurrent dashboard workers from initializing the database at the same time.

The changes eliminate a lock-file race that could lead to DuckDB catalog write conflicts during concurrent startup or refresh activity.

When an initializer is already active:

* A second worker waits for the active initializer to finish.
* The existing timeout behavior remains in effect.
* The waiting worker does not replace the active lock file.

This improves reliability during concurrent dashboard startup and refresh activity.

## Release Summary

Dataiku Pulse 3.1.1 and 3.2.1 expand the platform's reporting and governance capabilities while strengthening the reliability of its underlying data-processing and dashboard infrastructure.

The releases focus on four primary areas:

* **Expanded visibility** through license utilization and history-aware reporting.
* **Improved governance workflows** through Project Standards integration.
* **Greater data-processing reliability** across GOLD, SILVER, DuckDB, and S3.
* **Improved dashboard resilience** during startup, refresh, filtering, and partial-data scenarios.

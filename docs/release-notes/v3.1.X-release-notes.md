# Dataiku Pulse v3.1.0 Release Notes

**Release date:** TBD  
**Availability:** Controlled customer rollout

## Highlights

### More reliable GOLD table builds

Create GOLD Tables now applies resource-aware DuckDB limits for its own run.
It uses 40% of the memory available to the running container and two DuckDB
threads, preserving headroom for staging and managed-folder operations during
large fact-table builds.

### Improved audit-log and event-mapping data quality

- Improved handling of audit metadata fields that belong in `extras`.
- Strengthened event-mapping normalization so current mapping rules take
  precedence over stale historical mapping fields.
- Added safer historical event-mapping repair behavior, including replacement
  verification before source cleanup and clearer failure reporting.

### Scalable SILVER maintenance

The new **Compact SILVER Layer** custom recipe consolidates historical SILVER
event-mapping files at the existing category/module/instance/day partition
level. It is designed for large managed folders and includes:

- native, prefix-scoped cloud object discovery for Amazon S3, Azure Blob, and
  Google Cloud Storage;
- managed memory through a temporary local queue and bounded processing;
- recent-partition protection, avoiding the most recent two calendar days;
- optional module filtering for controlled maintenance runs;
- write, verification, and source-deletion safeguards; and
- an audit dataset with per-partition outcomes.

This is an administrator-operated repair and maintenance capability. It is
not scheduled automatically.

### License utilization metrics

Added license utilization and entitlement data to support expanded license
reporting, including a correction to assigned-profile sourcing.

### Security maintenance

Updated the `sqlparse` dependency as part of security maintenance.

## Upgrade notes

- No manual schema migration is required for standard GOLD-table builds.
- Existing GOLD builds retain their table names, storage locations, and
  partition layout.
- The old `reload-silver-layer` and `reload-event-mapping` macros have been
  replaced by the Compact SILVER Layer recipe for historical event-mapping
  maintenance.
- For large historical SILVER repairs, begin with a limited module filter and
  review the generated audit dataset before widening the scope.

## Controlled-rollout note

v3.1.0 is being introduced first to a limited customer group. The standard
GOLD build path has completed runtime validation. Broad historical Compact
SILVER runs should remain operator-controlled while customer storage layouts
and historical source files are validated.

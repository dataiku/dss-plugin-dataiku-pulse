# Pulse v3.1 Hardening Release Notes

This release focuses on pipeline correctness and operability: silent-failure paths now
either recover safely or fail loudly, and every Pulse-created scenario can notify on failure.

## ⚠ Required migration action: silver reload for casting fix

Casting configuration previously listed singular column names (`dataset_*`, `project_*`)
while the silver layer actually produces plural prefixes (`datasets_*`, `projects_*`, the
`list_*` collector convention). The casts therefore silently never applied, and existing
silver parquet stores these column families as **strings**:

- numeric: `projects_versiontag_versionnumber`, `projects_creationtag_versionnumber`,
  `datasets_versiontag_versionnumber`, `datasets_creationtag_versionnumber`
- datetime: `projects_versiontag_lastmodifiedon`, `projects_creationtag_lastmodifiedon`,
  `datasets_versiontag_lastmodifiedon`, `datasets_creationtag_lastmodifiedon`
- boolean: `projects_tutorialproject`, `datasets_managed`, `datasets_featuregroup`
- upper-cased string: `datasets_type`

From this release the casts apply, so newly written silver files carry proper
numeric/datetime/boolean dtypes. **Mixed dtypes across old and new silver files will break
gold builds that scan both.** After upgrading, run the **`reload-silver-layer`** macro once
per instance in the same maintenance window to rewrite historical silver with the corrected
dtypes.

Downstream note: gold specs reference these columns only through generic templates
(`SELECT *` history snapshots), and the dashboard SQL that consumes them
(`base_asset_index.yaml`, dashboard init SQL) already wraps them in `try_cast(...)`, so a
partially reloaded state degrades to NULLs rather than erroring — but reload promptly to
avoid silent NULLs in asset freshness columns.

## Behavior changes in this release

### Cursor safety (audit logs, projects)

Gather cursors no longer advance past failures — previously failed chunks, failed
projects, truncated file selections, and unreadable audit files were silently skipped
forever:

- Audit gather clamps its cursor to the earliest failed chunk / unreadable file /
  `max_files`-excluded eligible file. The macro summary row now reports
  `clamped_by_failures`, `file_read_failures` and `excluded_eligible_files`.
- A failed final event-mapping upload now clamps the cursor to that group's day instead
  of discarding the whole run's cursor progress.
- Project gather clamps its cursor 1s below the earliest failed project's
  `lastModifiedOn`, so failed projects re-qualify next run. One broken project no longer
  aborts the rest of the run (per-project isolation).
- A repeated failure now means repeated re-collection of the same window (visible in
  logs/summary) instead of silent data loss. Watch for `clamped_by_failures=true`.
- The projects delta fallback default was corrected from `2026-01-01` to
  `2015-01-01 00:00:00` (matching the parameter-set default); fresh installs no longer
  skip most existing projects.

### Plugin directory is no longer self-mutated

- The gold recipe renders the `{wide_columns}` license placeholder at runtime instead of
  rewriting its installed spec YAML (new license profiles are now picked up on every run).
- The silver normalizer no longer auto-writes `TODO_*.yaml` flatten stubs into the
  installed plugin directory (`PULSE_AUTO_TODO_FLATTEN` now defaults to off).

### New: failure notifications on all Pulse-created scenarios

Two new settings in the PULSE Dashboard parameter set:

- **Notification email** — recipient for a failure reporter (fires at scenario end on
  FAILED/ABORTED) added to every Pulse-created scenario: the four worker gather/cleanup
  scenarios on every worker host, and `gold_data_refresh` on the hub. Empty (default)
  disables the feature and removes previously created Pulse reporters on the next init.
- **Notification messaging channel id** — optional; when empty, the single mail channel
  on each target instance is auto-selected. With 0 or several mail channels the reporter
  is skipped with an actionable message in the init result table (init still succeeds).

The reporter is named `pulse_failure_email` and is re-applied idempotently on every init
run; reporters added by users are never modified. Reporter payload shape, run-condition
syntax and Freemarker variables were captured live from DSS 14.7 via
`scripts/verify_api_shapes.py` — re-run that script against the oldest DSS in your fleet
before upgrading if you run older versions.

### ⚠ Failures are now loud (previously-"green" broken runs will start failing)

Runs that silently produced broken or partial data now fail or warn visibly. After
upgrading, expect some scenarios that always showed green to report problems — that is
the fix working, not a regression:

- **Gold recipe fails on errors.** Any gold table that fails to build or unload now
  raises (new recipe param `fail_on_errors`, default on) — which triggers the new failure
  email. Tables skipped because no silver data exists yet are listed in `skipped_tables`.
- **Schema-drift DQ.** Silver writes where most flatten-contract columns are entirely
  NULL (payload no longer matches the contract) are routed to `silver_fail` with a
  `required_all_null` reason instead of being stored as all-NULL rows.
- **Missing flatten configs surfaced.** Collections without a flatten contract
  (unbounded schema) are counted in a new `flatten_missing_total` summary row.
- **Cursor writes report failure** (`cursor_write_failed` row) instead of a log-only
  warning.
- **event_mapping**: rows whose msgType is missing from mapping.csv are dropped and
  counted loudly (they previously flowed through unmapped); the `message_` prefix strip
  is now anchored so columns merely containing "message_" are no longer mangled.
- **Timestamp sanity clamp**: converted timestamps outside [1990-01-01, now+10y] are
  nulled and counted (epoch unit-detection mistakes no longer poison partitions).
- **Init**: when several Pulse presets exist, init reports which one it picked; the
  per-worker "Parameter Set" override in worker hosts is now honored (previously ignored).

### Misc

- The dashboard's cross-process DuckDB init lock directory is now created at startup
  (the fcntl lock previously could never be acquired).
- Removed a duplicate `gunicorn` pin from the code-env spec.
- Dead modules removed (`data_collection/data_collection/{parquet_writer,raw_transform,
  writers}.py` and the `processing/` package, plus the duplicate
  `pulse_duckdb/helpers/yaml_loader.py`). The `fact_dev_activity_events` schema is now
  declared once in `shared_duckdb/schemas.py`. **After upgrading the plugin, reload it /
  restart webapp backends** — DSS caches plugin code and stale imports of the removed
  modules would otherwise linger until restart.
